# نظام إدارة مدرسة النهضة (الخرطوم + عطبرة)

نظام إداري متكامل بقاعدة بيانات **موزعة**: قاعدة MySQL مستقلة لكل فرع، وخادم Express (جافا سكريبت) يوجّه كل عملية لعقدتها ويدمج النتائج، وواجهة React عربية.

> كل البيانات المزروعة **وهمية بالكامل** لأغراض التجربة والعرض.

---

## 1) المتطلبات

- **Node.js** نسخة 18 أو أحدث (`node --version` للتأكد)
- **Docker** (الأسهل) أو سيرفر **MySQL 8** محلي

## 2) التشغيل خطوة بخطوة

### الخطوة 1 - فك الضغط
فك ضغط الملف وافتح الطرفية (Terminal/CMD) داخل مجلد المشروع.

### الخطوة 2 - تشغيل قاعدتي البيانات

**الخيار أ (Docker - مفضل):**

أولاً عيّن كلمة مرور قاعدة البيانات بنفسك (لا توجد كلمة جاهزة في المشروع):
```bash
cp .env.example .env   # في Windows: copy .env.example .env
```
افتح ملف `.env` واكتب كلمة مرور من عندك في `DB_PASSWORD`، ثم:
```bash
docker compose up -d
```
ينشئ قاعدتين: `nahda_khartoum` على المنفذ 3307 و `nahda_atbara` على المنفذ 3308. بدون تعيين `DB_PASSWORD` سيرفض الأمر العمل برسالة واضحة.

**الخيار ب (MySQL محلي بدون Docker):**
```bash
mysql -u root -p < sql/create-local-databases.sql
```
ثم في ملف `backend/.env` غيّر المنفذين `DB_PORT_A` و `DB_PORT_B` إلى `3306`.

### الخطوة 3 - إعداد الخادم
```bash
cd backend
cp .env.example .env   # في Windows: copy .env.example .env
npm install
```

افتح ملف `.env` وعدّل:
- `DB_PASSWORD` إلى **نفس** كلمة المرور التي كتبتها في ملف `.env` بجذر المشروع
- `JWT_SECRET` إلى نص عشوائي طويل من عندك - **مطلوب**: الخادم يرفض العمل بدونه أو بقيمة جاهزة
- `DATA_ENCRYPTION_KEY` ولّده بالأمر التالي والصق الناتج في الملف:
```bash
npm run setup:key
```

### الخطوة 4 - إنشاء حسابات الدخول
كل حساب تُعيّن كلمة مروره بنفسك عبر متغير بيئة (لا توجد كلمات مرور جاهزة في الكود):

```bash
ADMIN_PASSWORD='اختر-كلمة-قوية' npm run setup:users
```

> هذا الأمر ينشئ الجداول تلقائياً عند أول تشغيل على قاعدة فارغة، لذلك لا يهم إن نفّذته قبل `npm start` أو بعده.

ولإنشاء بقية الحسابات دفعة واحدة:
```bash
ADMIN_PASSWORD='...' KHARTOUM_MANAGER_PASSWORD='...' ATBARA_MANAGER_PASSWORD='...' KHARTOUM_REGISTRAR_PASSWORD='...' ATBARA_REGISTRAR_PASSWORD='...' npm run setup:users
```

لتغيير كلمة مرور حساب لاحقاً: نفس الأمر مع متغير ذلك الحساب فقط.

على Windows (CMD) عيّن المتغيرات هكذا قبل الأمر:
```cmd
set ADMIN_PASSWORD=اختر-كلمة-قوية
npm run setup:users
```

وعلى PowerShell:
```powershell
$env:ADMIN_PASSWORD="اختر-كلمة-قوية"
npm run setup:users
```

### الخطوة 5 - التشغيل
```bash
npm start
```
أول تشغيل ينشئ الجداول ويزرع البيانات الوهمية في الفرعين تلقائياً. إذا كانت قواعد البيانات ما زالت تقلع (حاويات Docker تحتاج حوالي 30 ثانية أول مرة) يعيد الخادم المحاولة تلقائياً حتى تجهز.

افتح المتصفح على: **http://localhost:4000**

> الواجهة مبنية وجاهزة داخل `frontend/dist`. للتطوير على الواجهة: `cd frontend && npm install && npm run dev` ثم افتح http://localhost:5173

## 3) الحسابات والصلاحيات

| اسم المستخدم | الدور | الصلاحيات |
|---|---|---|
| `admin` | مدير المدرسة | كل شيء على الفرعين: عرض وإضافة وتعديل وحذف ونقل طلاب بين الفروع وإنشاء فروع |
| `khartoum.manager` | مدير فرع الخرطوم | إدارة فرعه فقط (طلاب ومعلمون وفصول ودرجات وحضور) بما فيها الحذف |
| `atbara.manager` | مدير فرع عطبرة | إدارة فرعه فقط بما فيها الحذف |
| `khartoum.registrar` | مسؤول تسجيل الخرطوم | إضافة/تعديل طلاب فرعه ودرجاتهم وحضورهم فقط - بلا حذف ولا إدارة معلمين أو فصول |
| `atbara.registrar` | مسؤول تسجيل عطبرة | مثل السابق على فرع عطبرة |

الصلاحيات مفروضة على **الخادم** (وليس الواجهة فقط): مدير فرع لا يستطيع الوصول لبيانات الفرع الآخر حتى بطلب مباشر.

## 4) الأمان المطبق

- **كلمات المرور**: تجزئة بخوارزمية bcrypt (اتجاه واحد) - لا تُخزن ولا تُسترجع كنص.
- **تشفير الحقول الحساسة**: هاتف ولي الأمر مشفر بـ AES-256-GCM داخل قاعدة البيانات، والمفتاح في ملف `.env` فقط (خارج قاعدة البيانات). **فقدان المفتاح يعني عدم القدرة على قراءة هذه الحقول** - احتفظ به في مكان آمن.
- **رموز الدخول JWT**: تنتهي صلاحيتها بعد 12 ساعة.
- **التحقق من المدخلات** ورسائل خطأ عربية واضحة.
- **استعلامات مُعامَلة (Parameterized)** ضد حقن SQL.
- **عزل الفروع** على مستوى الخادم حسب دور المستخدم.

## 5) كيف تعمل التوزيعة؟

- `branches` كتالوج عام مكرر في كل العقد يحدد أي عقدة تملك أي فرع.
- بيانات كل فرع (طلاب/معلمون/فصول/درجات/حضور) تعيش فقط في قاعدته.
- عرض "كل الفروع" = استعلام موزع يجمع من العقدتين ويوسم كل سجل بعقدته.
- تعطل عقدة لا يوقف الأخرى، وصفحة "حالة العقد" تعرض الاتصال لحظياً.
- نقل طالب بين الفرعين ينسخ سجلاته ثم يحذف الأصل؛ عند انقطاع الاتصال أثناء النقل قد يتكرر السجل مؤقتاً ويُحذف يدوياً (لا معاملات موزعة ذرية في هذه النسخة - موثق في التحليل).

## 7) استكشاف الأخطاء

| المشكلة | الحل |
|---|---|
| `قاعدة البيانات غير متاحة` | تأكد أن Docker يعمل ونفّذ `docker compose ps` - يجب أن تكون القاعدتان healthy |
| `JWT_SECRET غير مضبوط` عند التشغيل | افتح `backend/.env` وعيّن نصاً عشوائياً طويلاً من عندك (متعمد: لا توجد قيمة جاهزة) |
| `DB_PASSWORD غير مضبوط` | عيّن كلمة مرور القاعدة في `backend/.env` بنفس قيمة `.env` الجذري |
| المنفذ 3307 أو 3308 مشغول | غيّر المنافذ في `docker-compose.yml` و `.env` معاً |
| `بيانات مشفرة بلا مفتاح` | أعد لصق `DATA_ENCRYPTION_KEY` الصحيح في `.env` |
| `الجلسة غير صالحة` | سجل الدخول من جديد (الرمز يعيش 12 ساعة) أو تأكد أن `JWT_SECRET` لم يتغير |
| نسيت كلمة مرور حساب | أعد تشغيل `npm run setup:users` مع متغير ذلك الحساب بكلمة جديدة |

## 8) حدود هذه النسخة

نسخة تعليمية/عرض: لا توجد نسخ احتياطية تلقائية (Replication)، ولا معاملات موزعة ذرية، ولا HTTPS مدمج. قبل أي استخدام ببيانات حقيقية راجع قسم التطوير المستقبلي في ملف التحليل.
